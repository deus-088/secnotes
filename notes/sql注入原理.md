# SQL注入原理

## 一、SQL注入的原理
### 1.1 概况
当Web应用向后台数据库传递SQL语句进行数据库操作时，如果对用户输
入的参数没有经过严格的处理，那么攻击者就可以构造特殊的SQL语句， 
直接输入数据库引擎执行，获取或修改数据库中的数据。
> 个人理解：用户的输入被当成了SQL语句执行了

*强调了一定要学会手动写sql语句，不能纯靠工具*

### 1.2 两个关键点
> 强调：所有的漏洞都是有条件的！！后续所有漏洞都是

**一般地，SQL注入漏洞有以下两个条件：**
#### 1.2.1.输入内容用户可控
- 用户能够控制输入的内容

例如注册账户时，需要选择性别。性别只有“男”“女”“不可透露”可选，不是用户可控输入的，这就不符合条件，无法构造sql语句（相反的，如果没有选项可选，就是主动可控）

#### 1.2.2.用户输入被带入数据库
- Web应用能把用户输入的数据带入数据库中执行

为了应对这种情况，常采用**预编译技术**：先把SQL语句的结构发给数据库**编译**，用户输入之后只作为“参数值”传进去，不参与SQL语法解析。

也就是说，用户输入仍然会进入数据库，但数据库只把它当数据，不会把它当SQL代码执行

## 二、SQL注入的危害
### 2.1 三个危害
- 盗取网站敏感信息
- 绕过网站后台验证
- 后台登录语句：
```sql
例如：SELECT * FROM users WHERE username='$users' and password='$pass'
                                            T    and      T     =》 T
星号*表示所有，FROM表示从users数据表里查询数据，WHERE是内容，and是逻辑运算符（两真才是真）
```

2.2 恒真注入（万能密码）
```sql
'or '1'='1'#  或者  'or 1=1#
```

 '#'号的含义：一个注释符，Mysql中其它注释符还有：`--空格` `--＋` `%23` 

（加号＋在URL编码中会被自动编码为空格，%23也会被解码成空格

> 注意：#井号在GET型注入中不能用，POST可以用，原因是：#井号在URL地址中表示锚点（一个定位符，用于定位），

2.3 恒真注入演示过程
为方便理解，展示一下恒真注入时，**最开始**的**理想状态**：
```sql
SELECT * FROM users WHERE username=''or 1=1# and password='1111'
```
可是由于#号代表了注释符，后面的内容被·注释掉了，所以**实际上**是下面这样：
```sql
SELECT * FROM users WHERE username='' or 1=1
                                   F  or  T   =》 T
```
or逻辑：一真一假都是真；（区别于and逻辑：两真才是真）


万能密码原理：通过or语句的逻辑性质，配合1=1恒真性与注释符忽略掉密码核对请求，使得整个WHERE条件恒真，可能会返回所有用户
