# SecNotes · 个人网络安全笔记库

纯静态的个人博客 / 笔记库。所有内容以 Markdown 存放在 `notes/` 目录，运行一次构建脚本即可生成站点，
**无需数据库、无需后端、无需联网**，双击 `index.html` 就能看。

---

## 快速开始

### 方式一：网页管理端 + 一键同步（推荐）

```bash
# 只做一次：双击 start-admin.bat（或运行 python admin.py），保持窗口开着
```

然后双击 **`manage.html`** 写笔记。**点保存 → 弹窗确认 → 自动写回 `notes/` 并运行 `build.py`**，
展示端会自动刷新看到新内容，全程不用敲命令。

| 端 | 文件 | 用途 |
| --- | --- | --- |
| **展示端** | `index.html` | 纯阅读：首页、文章、归档、标签、检索。双击即可打开，**没有任何管理入口** |
| **管理端** | `manage.html` | 增删改笔记、实时预览、双向链接。双击即可打开 |
| **同步服务** | `admin.py` / `start-admin.bat` | 代执行"写回 `notes/` + 重建"两步（浏览器不能自己启动进程） |

> **为什么需要一个常驻服务**：浏览器出于安全限制，既不能读写任意本地文件，也不能启动进程。
> 所以"保存即生效"这条链路由本地服务代劳；管理端通过 `http://127.0.0.1:8080/api/sync`
> 把笔记交给它，令牌用 JSONP 自动获取（`file://` 页面可跨域加载脚本），无需手工抄写。
> 服务没启动时，管理端自动退回导出模式，并提示启动命令。

服务未运行时的兜底方式：

```bash
# 方式 A：导出 notes.json，一条命令写回 notes/ 并重建
python build.py --from-json notes.json

# 方式 B：Chrome / Edge 点「写入 notes/ 目录」，选一次 notes 文件夹直接写盘，再 python build.py
```

### 方式二：本地服务编辑器（`admin.py`，改动直接落盘）

```bash
python admin.py
# 终端会打印一个带访问令牌的地址，用浏览器打开它
#   编辑器   http://127.0.0.1:8080/?token=xxxxxx
#   站点预览 http://127.0.0.1:8080/index.html
```

这个版本的编辑器直接读写 `notes/` 目录（删除走回收站、可还原），保存即自动重建站点数据。
代价是必须启动服务；不想启动服务时用方式一。

### 方式三：命令行

```bash
# 1. 新增一篇笔记（自动生成带格式的模板）
python new-note.py "Nmap 实战用法" -c "渗透测试" -t "Nmap,信息收集"

# 2. 编辑 notes/ 下的 Markdown 文件

# 3. 重新构建站点数据
python build.py

# 4. 本地预览
python -m http.server 8080
```

> 站点本身是纯静态的：直接双击 `index.html` 也能完整浏览（笔记数据内联在 `data/notes.js`，
> 不依赖网络与本地文件读取）。管理端 `manage.html` 同样是双击即用，只是**改动存在浏览器本地**，
> 需要导出/`--from-json` 才写回磁盘——浏览器不允许网页在用户不知情时写本地文件。

## 笔记格式

在文件开头写 front-matter：

```markdown
---
title: SQL 注入：从原理到防御的完整链路
date: 2026-09-10
category: Web 安全
tags: [SQL注入, OWASP, 数据库]
summary: 一句话摘要（可省略，省略时自动截取正文首段）
---

# 正文标题

正文内容，支持 GFM 表格、任务列表、代码高亮。
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 否 | 省略时取正文首个标题，再退回文件名 |
| `date` | 否 | `YYYY-MM-DD`，省略时取文件修改时间 |
| `category` | 否 | 省略为「未分类」 |
| `tags` | 否 | 支持 `[a, b]` 或逗号分隔 |
| `summary` | 否 | 首页卡片摘要，建议 60–130 字 |
| `slug` | 否 | URL 标识，省略时由文件名生成 |
| `draft` | 否 | `true` 时构建跳过，不收录 |

正文里可以用 `[[另一篇的标题]]` 建立双向链接，详见「内容管理 → 双向链接」。

命名约定：`<分类前缀>-<序号>-<英文短名>.md`，例如 `web-01-sql-injection-basics.md`。
以 `_` 开头的文件会被构建脚本忽略（适合放草稿）。

### 标题与右侧目录

文章右侧的「目录」是**自动生成**的，规则如下：

| 写法 | 结果 |
| --- | --- |
| `## 一、背景` | 二级标题，进目录 |
| `### 1.1 细节` | 三级标题，进目录 |
| `#### 更细一层` | 四级标题，进目录 |
| `# 正文标题` | 一级标题是文章标题，**不进目录** |
| `##### 五级` | 太深，不进目录 |

两个容易踩的点：

1. **`#` 后面必须跟一个空格**。写成 `##三、补充目录111`（漏空格）时，Markdown 规范不认它是标题，
   只会渲染成普通段落——字号比相邻标题小一截，也进不了目录。
   本项目已在渲染层做容错：漏空格会自动补上，与 `## 一、` 字号完全一致；但仍建议按规范写。
2. **目录少于 2 条就整栏不显示**。只写一个 `##` 的话，右侧不会有目录。

标题请单独成行；写成列表项（`- ### 标题`）虽然也能渲染，但样式是嵌在列表里的，不推荐。

## 管理端 `manage.html`（免服务，双击即用）

| 能力 | 说明 |
| --- | --- |
| **首次打开** | 自动从 `data/notes.js` 导入站点现有笔记，随后以浏览器本地库为准 |
| **新建 / 修改 / 删除** | 左侧列表选笔记，右侧编辑；删除前有确认；同名文件拒绝覆盖 |
| **实时预览** | 与展示端文章页同一渲染链路（同一个 `render.js`），所见即所得 |
| **双向链接** | 输入 `[[` 联想标题；面板实时显示**出链 / 入链 / 待创建**，点「待创建」直接按标题新建 |
| **搜索** | 标题 / 分类 / 标签 / 正文，多关键词为 AND |
| **分类** | 左侧下拉列出已有分类（带篇数），选中即填入；也可以直接在输入框敲一个新名字来新建分类 |
| **保存即同步** | 点保存 → 确认 → 自动写回 `notes/` + 运行 `build.py`，展示端自动刷新（需服务在跑） |
| **删除也同步** | 管理端删除的笔记，同步时移入 `.trash/` 回收站，可还原，不做物理删除 |
| **服务不在时** | ① Chrome / Edge 点「写入 notes/ 目录」真写盘；② 导出 `notes.json` + `python build.py --from-json notes.json`；③ 逐篇下载 `.md` |
| **备份** | 导出 JSON 留底，换机器时用「导入」恢复 |

搭建要点：所有资源都是**相对路径**（`assets/…`、`data/notes.js`），因此 `file://` 双击可用；
页面不读取本地文件（那会被跨域拦），数据走 localStorage 与本地服务。

## 内容管理（`admin.py` 服务版编辑器）

```bash
python admin.py                 # 默认 http://127.0.0.1:8080
python admin.py --port 9000     # 换端口
python admin.py --no-rebuild    # 保存后不自动重建（自行运行 build.py）
```

### 入口与界面

- 启动后打开终端打印的地址即可；改动直接读写 `notes/` 目录，保存即自动重建。
- 编辑器界面与站点**同一套主题变量、配色与卡片语言**（顶栏、按钮、列表卡片与站点一致）。
- `admin/index.html` 不能直接双击打开（拿不到令牌、读写不了笔记）；若误以文件形式打开，
  页面会显示全屏启动指引，而不是一个"点了没反应"的界面。
- 不想启动服务时，用上面那节的管理端 `manage.html`。

### 能做什么

| 操作 | 说明 |
| --- | --- |
| **新建** | 左侧「＋ 新建笔记」，自动生成正文骨架；文件名留空则由标题生成 |
| **修改** | 元信息（标题 / 日期 / 分类 / 标签 / 摘要 / 草稿）用表单填写，正文用 Markdown 编辑 |
| **改名** | 修改「文件名」字段即可，旧文件会自动删除 |
| **删除** | 移入 `.trash/` 回收站而非直接抹除，可在「回收站」标签页**还原**或彻底删除 |
| **分类 / 标签** | 分类带自动补全；标签用逗号分隔，保存时自动拆分 |
| **全文检索** | 左侧搜索框按**标题、分类、标签与正文**检索；正文命中给出所在行，点一下直接跳到那一行 |
| **双向链接** | 正文里写 `[[笔记标题]]` 即可互相引用；输入 `[[` 会联想标题，面板实时显示出链 / 入链 / 待创建 |
| **插图** | 截图可直接**粘贴**或拖入编辑区，也可点「图片」选择文件；自动上传并插入 Markdown |
| **草稿保护** | 编辑内容每 1.5 秒自动存一份本地草稿，浏览器崩溃或误关标签页后可恢复 |
| **实时预览** | 右侧边写边渲染，与站点文章页为同一渲染链路 |
| **重建站点** | 保存时自动重建；也可点顶栏「重建站点」手动触发 |

**保存时会自动运行 `python build.py`**，因此刷新站点页面即可看到改动，不需要额外命令。

### 双向链接

正文里用 `[[笔记标题]]` 互相引用，也支持 `[[笔记标题|显示文字]]` 自定义链接文字。

**输入时**：敲下 `[[` 会弹出标题联想面板（也可点工具栏的 `[[ ]] 双链`），
继续输入即过滤，<kbd>↑</kbd><kbd>↓</kbd> 选择、<kbd>Enter</kbd> 或点击插入、<kbd>Esc</kbd> 取消。

**编辑区上方**有一个双向链接概览，实时显示三组信息：

| 分组 | 含义 | 点击行为 |
| --- | --- | --- |
| **出链** | 本篇正文引用到的笔记 | 打开那篇笔记 |
| **入链** | 引用了本篇的其他笔记（反链） | 打开那篇笔记 |
| **待创建** | 指向了还不存在的标题 | **按该标题新建一篇**，填好内容保存即可接上 |

**站点上**，笔记底部会显示「反向链接」面板，除了来源标题，还附上**引用处的原文片段**，
方便判断上下文；指向不存在笔记的链接会显示为虚线样式并标注「尚未创建该笔记」，
而不会静默失效或跳错页面。

链接目标先按**标题**匹配（大小写不敏感），再退回按 **slug** 匹配；同一目标重复引用会自动去重，
自引用不计入出链。

> 链接图由 `build.py` 统一计算并写入 `data/notes.js`，编辑器通过 `/api/state` 拿到**同一份**结果
> （两边调用同一个 `build_link_graph()`），因此站点与编辑器对"谁引用了谁"的判断始终一致。
> 构建时会打印 `🔗 双向链接 : N 条出链，M 篇被引用，K 个待创建`。

### 全文检索

左侧搜索框覆盖**标题、分类、标签与正文**，输入即检索（250ms 防抖）：

- 多关键词用空格分隔，语义为 **AND**——每个词都必须出现，但可以分布在不同行。
- 正文命中会按行列出，点击任一片段即打开该笔记并**选中命中所在的那一行**；按 <kbd>Enter</kbd> 直接跳到第一条命中。
- 标题命中的笔记排在前面，并标注「正文 N 处」或「标题/标签命中」。
- <kbd>Esc</kbd> 清空检索并恢复普通列表。
- 下划线开头的草稿文件不参与检索。

**中文会做一次放宽匹配**。原因是中文没有词边界，只做精确子串匹配时，搜「内网渗透」会因为
笔记里写的是「内网探测」「渗透测试」而返回 0 条。因此精确匹配无结果时会自动把较长的中文词切成
相邻二字组再匹配一遍，并在界面上明确标注「未找到完整匹配，以下是放宽为词组后的相近结果」——
**放宽结果一定会被如实告知，不会伪装成精确命中**。

### 代码框功能

工具栏的 `{ } 代码块` 按钮（或 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>C</kbd>）会弹出语言选择框：

- 语言列表**直接读自 highlight.js 的支持集**，选中的语言必定能高亮；也支持手动输入
- 插入时会自动在围栏前后补齐空行——避免与正文粘连导致 Markdown 解析异常
- 围栏内已有选中文本时，会直接把这些文本包进代码块
- 插入后光标停在围栏内部，可直接开始输入

**渲染效果与站点完全一致**——这不是靠人工对齐，而是编辑器预览与站点正文调用同一个
`assets/js/render.js`，且共用同一份 `style.css`。因此代码块的圆角容器、右上角语言标签、
悬停出现的复制按钮、语法高亮配色在两处完全相同。测试脚本里有一项直接比对：同一段
Markdown 在两侧的渲染结果**逐字符相同**。

### 插入图片

安全笔记里截图很常见，所以三种方式都能插图：

| 方式 | 操作 |
| --- | --- |
| 粘贴 | 截图后在正文里直接 <kbd>Ctrl</kbd>+<kbd>V</kbd> |
| 拖入 | 把图片文件拖到正文区域（拖入时编辑区会高亮） |
| 选择 | 点工具栏「图片」选择本地文件，支持多选 |

图片会被上传到 `assets/uploads/<年月>/`，文件名由**内容摘要**生成——同一张图重复上传不会产生冗余文件。
插入的 Markdown 使用**相对路径**（`![图片](assets/uploads/...)`），因此站点即使直接双击 `index.html`
打开也能正常显示图片。插入后会自动选中替代文字，直接输入即可改成图注。

限制：仅支持 `png` / `jpg` / `gif` / `webp`，单张不超过 8MB。

> **刻意不支持 SVG**：SVG 可以内嵌脚本，一旦站点公开部署就会变成同源 XSS 的载体。

日积月累难免产生不再被引用的图片，可以随时查看并清理：

```bash
python build.py --gc-images           # 只列出，不删除
python build.py --gc-images --yes     # 确认后删除
```

清理时会把 `notes/` 下的**全部** Markdown（含草稿与 `_` 前缀文件）以及 `.trash/` 一起纳入比对，
所以草稿和可还原笔记用到的图片不会被误删。

### 草稿自动保存

编辑内容每 1.5 秒在浏览器里存一份草稿（按笔记分开保存），状态栏会显示「草稿已自动保存 hh:mm」。

下次打开这份笔记时，若草稿与磁盘版本不一致，会弹窗询问是否恢复：

- 选**恢复草稿** → 编辑区载入草稿内容，核对后自行保存
- 选**不用，用磁盘版本** → 载入磁盘内容，但**草稿仍原样保留**，不会丢失未保存的内容

保存成功后草稿即被清除。

### 安全说明

编辑器是本机工具，做了这几层限制：

1. **只监听 `127.0.0.1`**，不对外网开放；
2. 每次启动生成**随机访问令牌**，所有接口请求必须携带该令牌；同时校验 `Origin`，
   防止本机其他页面发起跨站请求篡改笔记；
3. **静态资源按白名单提供**：只开放 `index.html`、`assets/`、`data/`、`admin/`。
   `notes/`、`.trash/`、`.workbuddy/`、服务端源码与配置文件**一律不经 HTTP 暴露**，
   以点开头的目录全部拒绝；
4. 文件名走白名单校验并强制限定在 `notes/` 目录内，**阻断目录穿越**；
5. **删除是移入回收站**，不是抹除，可还原；
6. 新建时若同名文件已存在会**直接拒绝**，不会静默覆盖已有笔记；
7. 上传只接受图片的 base64 数据、按内容摘要重命名，不接受客户端指定的文件名与路径。

令牌会打印在终端里，页面加载后会自动从地址栏移除，避免被误复制分享。

## 功能

- **全文检索**：标题（权重最高）、标签、分类、摘要、正文加权计分，多关键词空格分隔，命中处高亮；按 `/` 快速聚焦搜索框
- **分类与标签筛选**：侧边栏一键过滤，URL 可分享（`#/category/Web%20安全`、`#/tag/SQL注入`）
- **分页加载**：首页每页条数由 `pageSize` 控制，底部「加载更多」按需追加内容——只追加 DOM 不整页重渲染，阅读位置不会跳动
- **归档视图**：按年份自动分组
- **文章页**：自动生成目录 + 滚动高亮、代码高亮与一键复制、表格自适应滚动、上/下一篇导航、阅读进度条
- **相关笔记**：文章底部按「同分类 3 分 + 每个相同标签 2 分」推荐最多 4 篇，并显式标出共同标签，便于笔记之间互相发现
- **反向链接**：文中用 `[[标题]]` 引用其他笔记，被引用页底部会列出所有引用来源并附上引用处原文片段
- **明暗双主题**：右上角切换（快捷键 `t`），偏好写入 localStorage
- **响应式**：桌面为侧栏布局，移动端折叠为抽屉式导航
- **内容安全兜底**：渲染前剥离 `script`/`iframe`/`on*` 事件属性与 `javascript:` 链接

  "description": "……",

| 字段 | 说明 |
| --- | --- |

| `author` | 页脚署名 |
| `defaultTheme` | `dark` / `light`，仅影响首次访问 |
| `pageSize` | 首页每页条数，超过部分通过「加载更多」追加 |
| `siteUrl` | 部署后的站点地址（如 `https://notes.example.com`）。**留空则不生成订阅文件** |

改完重新构建（或直接刷新，标题会在运行时读取）。

## 开发自检

改动前端或服务端代码后，建议跑一遍回归（合计 509 项断言）：

```bash
node tools/verify-render.mjs    # 展示端渲染链路 + 目录规则 + 同步后自动刷新，83 项
node tools/verify-manage.mjs    # 管理端：file:// 可用性 / 增删改 / 工具栏 / 分类选择栏 / 预览收起 / 一键同步，118 项
node tools/verify-editor.mjs    # admin/ 编辑器交互 + 与站点的渲染一致性，146 项
python tools/verify-admin.py    # 内容管理服务 API（真实启动服务、真实增删改），145 项
node tools/e2e-chain.mjs        # 真实 Chrome：新建→保存→确认同步→notes/ 落盘→展示端可见→删除，17 项
```

**关于 `tools/fixtures/notes/`**：`verify-render.mjs` 的断言针对一份**固定内容**编写
（需要代码块、表格、有序列表、双向链接、足够多篇以触发分页等特征）。夹具在测试开始时
临时装入 `notes/`，结束后按快照**精确还原**并重建 —— 所以你可以随便增删自己的笔记，
渲染自检依然稳定，也不会把夹具留在你的站点里。
它会自检两件事：结束时 `notes/` 零残留、开始时没有被上次残留污染。

覆盖范围：

- **展示端**：首页、分页与「加载更多」、全文检索、分类筛选、文章页（Markdown / 代码块 /
  目录 / 表格 / 代码复制 / 相关笔记 / **反向链接**）、**双向链接的三种状态**
  （已解析 / 待创建 / 不应在代码块内展开）、归档、标签、主题切换、404 兜底、
  **不含任何管理入口**（断言页面上不存在管理按钮与相关文案）
- **管理端**：引用全为相对路径（`file://` 可用）、首次从 `data/notes.js` 导入、
  localStorage 持久化、新建 / 保存 / 删除 / 重名保护、搜索过滤与空态、
  **分类选择栏**（列出已有分类与篇数、选中即填入、保留自由输入新建分类）、
  双向链接面板（出链 / 待创建）、导出 md 的 front-matter 转义、导出 / 导入 JSON、
  **编辑器布局**（网格行数与子元素数一致、工具栏不与编辑区重叠，防止「整排按钮点击失效」）、
  **`[hidden]` 兜底**（被 `display` 覆盖时会真隐藏）、**预览收起 / 展开**（默认展开、
  收起后操作栏仍留展开入口、状态持久化）、
  **一键同步**（保存后弹确认、请求体含全部笔记与待移除列表、成功后标记已同步并通知刷新）、
  以及**同一段 Markdown 与展示端渲染结果逐字符比对**
- **编辑器**：列表与检索（含命中行跳转、回车跳转、Esc 清空、放宽匹配提示）、新建、
  代码块插入的五种边界情形（空选区 / 有选区 / 行中 / 行首 / 文末）、未支持语言的处理、
  全部工具栏动作、快捷键、保存与删除确认、图片插入与上传（粘贴 / 拖入 / 选择文件 /
  非图片拒绝）、草稿自动保存与恢复/放弃两条路径、
  **双向链接联想**（弹出 / 过滤 / 高亮 / 方向键 / 回车与点击插入 / Esc 抑制 / 不推荐自链）、
  **链接面板**（出链 / 入链 / 待创建 / 点击打开 / 按标题新建）、
  以及**同一段 Markdown 在站点与编辑器两侧的渲染结果逐字符比对**
- **服务**：`/api/sync` 一键同步（写入 / 覆盖 / 移入回收站 / 目录穿越清洗 / 自动重建）、
  `/api/token.js` 令牌下发（本地来源可取、第三方站点 403）、CORS 预检、
  `--from-json` 导入、令牌鉴权、静态资源白名单（笔记与回收站不经 HTTP 暴露）、全文检索
  （AND 语义 / 行号 / limit / 草稿排除 / 中文放宽匹配及其边界）、**链接图**
  （标题与 slug 解析 / 去重 / 自引用排除 / 待创建 / 站点与服务一致）、图片上传
  （去重 / 类型与体积校验 / SVG 拒绝）、目录穿越拦截、新建 / 修改 / 改名 / 删除 /
  还原 / 彻底删除、重名保护、图片清理工具、front-matter 往返一致、自动重建

`verify-admin.py` 只操作自己的临时笔记与临时图片（slug / 文件名以 `zz-verify` 开头）。

## 部署

纯静态站点，把整个目录（或至少 `index.html`、`assets/`、`data/`）上传即可：

- **GitHub Pages / Cloudflare Pages / Vercel / Netlify**：直接指定目录，无需构建命令
- **自有服务器**：放到 Nginx 的静态目录
- **内网共享**：`python -m http.server 8080` 后同事即可访问

> 公开部署时不需要上传 `admin.py`、`admin/`、`.trash/`、`notes/` 与 `tools/`——
> 它们只在本地写作时使用。保留 `index.html`、`assets/`（含 `assets/uploads/` 里的图片）、
> `data/` 三个即可。

> 提示：若要公开部署，请先检查笔记中是否包含真实目标信息、内网地址、凭据或个人隐私内容。
